# مدیر ارسال زمان‌بندی‌شده

این نمونه یک بنر را فقط به گروه‌هایی می‌فرستد که خودتان انتخاب کرده‌اید. انتخاب
خودکار شامل همهٔ گروه‌هایی است که حساب در آن‌ها عضو است و مجوز مؤثر ارسال پیام
(`send_message`) دارد؛ مدیر بودن یا مجوز افزودن عضو معیار نیست. فاصلهٔ ارسال
کمتر از ۱۰ ثانیه پذیرفته نمی‌شود و فاصلهٔ دورها را می‌توان از ۱ تا ۶۰ دقیقه
تنظیم کرد.

## اجرا

از ریشهٔ پروژه:

```bash
python3 -m pip install -e .
python3 -m examples.broadcast_manager
```

اجرای مستقیم نیز پشتیبانی می‌شود:

```bash
python3 examples/broadcast_manager/app.py
```

فرمان `!help` را از حساب خودتان در «پیام‌های ذخیره‌شده» بفرستید. هم ارسال مستقیم
فرمان و هم ویرایش یک پیام قبلی به فرمان پشتیبانی می‌شود، حتی اگر پیام پیش از
اجرای برنامه ساخته شده باشد. برنامه ابتدا همان پیام را به «در حال انجام» و سپس
به نتیجهٔ نهایی ویرایش می‌کند. اگر ویرایش نتیجه ممکن نباشد، نتیجه را به‌صورت پیام
جداگانه می‌فرستد.

نمونهٔ تنظیم:

```text
!banner جشنواره امروز؛ برای اطلاعات بیشتر پیام بدهید.
!groups all
!gap 20
!every 60
!start
```

برای نمونه، ارسال هر یک دقیقه:

```text
!every 1
```

برای افزودن همان گروهی که داخل آن هستید، فرمان زیر را در خود گروه بفرستید:

```text
!add
```

یا از `!groups add` استفاده کنید. برای افزودن چند گروه، یک پیام بسازید که در هر
خط آن یک لینک دعوت `ble.ir/join/...` باشد، روی آن ریپلای کنید و بفرستید:

```text
!addlinks
```

معادل کامل آن `!groups links` است. لینک‌ها یکی‌یکی و با محدودکنندهٔ درخواست
بررسی می‌شوند و فقط گروه‌هایی افزوده می‌شوند که حساب عضو آن‌هاست و مجوز
`send_message` دارد.

فرمان `!panel` پنل زیر را روی همان پیام باز می‌کند:

```text
- [x] ارسال زمان‌بندی‌شده
- [x] تلاش مجدد هنگام محدودیت
- [x] نمایش پیشرفت اسکن
```

روی چک‌باکس هر گزینه بزنید؛ بله پیام را به‌صورت خودکار ویرایش می‌کند و برنامه
تنظیم جدید را از همان ویرایش تشخیص می‌دهد. سپس همان پنل دوباره ویرایش می‌شود و
زیر آن بخش «آخرین تغییرات» نشان می‌دهد کدام قابلیت روشن یا خاموش شده است. ارسال
زمان‌بندی‌شده تا وقتی بنر و حداقل یک گروه تنظیم نشده باشد روشن نمی‌شود و علت آن
نیز زیر پنل نوشته می‌شود.

شناسهٔ ۲۰ پنل آخر در تنظیمات ذخیره می‌شود. دلیل آن این است که بله در بعضی
ویرایش‌های کلیکی `sender_uid` را صفر می‌فرستد؛ برنامه با شناسهٔ پیام تشخیص می‌دهد
که این همان پنلی است که قبلاً از فرمان حساب شما ساخته شده است. پس از به‌روزرسانی
برنامه حتماً با `!panel` یک پنل تازه بسازید.

پنل polling و درخواست دوره‌ای ندارد. تغییر چک‌باکس مستقیماً از raw update
وب‌سوکت پردازش می‌شود؛ در نتیجه برای پنل هیچ `sleep` یا درخواست history اجرا
نمی‌شود و پاسخ آنی است.

`!groups all` در حالت عادی فقط دو درخواست bulk خود بله را اجرا می‌کند:
`GetMyGroups` برای شناسه و `access_hash` همهٔ عضویت‌ها و `LoadGroups` برای اطلاعات
و مجوز مؤثر آن‌ها. بنابراین دیگر برای هر گروه `GetFullGroup` جداگانه نمی‌فرستد،
بین گروه‌ها `sleep` ندارد و معیار انتخاب فقط `send_message` است. دستور
`!groups count 5` نیز از همین پاسخ bulk پنج گروه اول مجاز را ذخیره می‌کند.

فقط اگر نسخهٔ قدیمی سرور این دو RPC را نشناسد، مسیر سازگاریِ صفحه‌بندی دیالوگ‌ها
فعال می‌شود. وقفهٔ `scan_gap_seconds` صرفاً متعلق به همین fallback قدیمی است. در
خطای موقت `user_rate_limited`، اگر گزینهٔ تلاش مجدد روشن باشد، مقدار
`retry_after` اعلام‌شده توسط خود سرور رعایت می‌شود؛ حذف اجباری این انتظار باعث
رفع محدودیت سمت بله نمی‌شود.

برای استفاده از یک پیام کامل شامل عکس، فایل یا متن به‌عنوان بنر، روی آن پیام
ریپلای کنید، یک پیام عادی بفرستید و سپس پیام جدید را به `!banner` ویرایش کنید.

تنظیمات در `sessions/broadcast-settings.json` ذخیره می‌شوند و وارد Git نمی‌شوند.

قبل از ارسال، رضایت اعضا و قوانین بله و گروه را رعایت کنید. این نمونه قابلیت
عضویت خودکار، جمع‌آوری کاربر یا دورزدن محدودیت سرویس را ندارد.
